Một item, đủ để tìm và dùng

- id: terminal-process-on-port
  title: Xem tiến trình đang giữ port
  type: command
  category: terminal
  aliases:
    - thằng nào giữ port
    - find process using port
  content: "lsof -nP -i :<port>"
  example: "lsof -nP -i :3000"
  note: "Thay <port> bằng số port cần kiểm tra."
  risk: safe

File chuẩn: data/<category>.yaml. Trong dev, lưu YAML sẽ cập nhật module. Production cần build lại. Không lưu item trong localStorage.

Hợp đồng dữ liệu

Trường Quy tắc
id Duy nhất toàn kho, chữ thường / số / gạch ngang; giữ ổn định.
title Nhu cầu dễ nhận biết, không rỗng.
type command, shortcut, path, config, snippet, concept, workflow, routine, fix.
category terminal, tmux, git, docker, macos.
aliases Danh sách chuỗi không rỗng, cách gọi Việt/Anh.
content Nội dung hiển thị và copy, không rỗng.
example Tùy chọn; ví dụ cụ thể, có nút copy riêng.
note Điều kiện, nền tảng, tác dụng; không rỗng.
risk safe, caution hoặc destructive.
riskNote Bắt buộc với caution/destructive; giải thích tác động.

Validator dùng chung ở src/data/schema.ts. Từ chối ID trùng, field không biết, sai type, chuỗi rỗng và collection không phải list không rỗng.

Ghi rõ tác động

safe

Tra cứu hoặc thao tác thông thường. Vẫn cần đọc note và thay tham số đúng.

caution

Có gián đoạn hoặc điều kiện đáng chú ý. Ví dụ restart service. Bắt buộc riskNote.

destructive

Xóa dữ liệu, mất thay đổi hoặc kết thúc tác vụ. Bắt buộc nêu tác động cụ thể.

Quy trình bổ sung

  1. Chọn đúng category, ID ổn định và duy nhất. Category mới cần cập nhật schema, UI và test.
  2. Viết title theo nhu cầu; aliases theo cách người dùng thật sự nhớ.
  3. Kiểm command/phím tắt bằng tài liệu chính thức; nêu điều kiện nền tảng và tool cần cài.
  4. Dùng <parameter> cho mẫu, example cho ví dụ. Không đưa secret/token hoặc máy chủ cá nhân vào seed.
  5. Chọn risk và viết riskNote khi có tác động.
  6. Chạy kiểm dữ liệu, test và xem trực tiếp query/nội dung copy.

Search bằng cách gọi

Chuẩn hóa dấu, chữ đ, chữ hoa và khoảng trắng. Tìm trên title, aliases, category, content và example. Ưu tiên title/alias hoặc command chính xác → cụm từ → token literal → fuzzy.

Fuzzy nhận một lỗi ký tự hoặc đảo hai ký tự liền nhau trong từ từ 3 ký tự. Số token fuzzy không quá max(1, floor(số token intent / 3)). Một token tối đa 3 ký tự không có category chỉ khớp literal; prefix từ từ 3 ký tự được hỗ trợ. Cache tối đa 200 token, không lưu query bền vững. Tên công cụ trong query giới hạn category tương ứng.

Chưa có semantic search. Thêm aliases khi cách diễn đạt thường dùng chưa tìm đúng.

Hai điểm dễ nhầm

tmux: Prefix mặc định Ctrl+B, nhấn rồi thả trước phím tiếp. % chia trái/phải; dấu " chia trên/dưới. Không giả định prefix cá nhân. UI dùng mũi tên cho hai bước, dấu cộng cho chord đồng thời. Workflow tên pane tách lệnh terminal và example lưu trong ~/.tmux.conf.

Git: restore --staged bỏ stage, giữ working tree. restore -- <file> bỏ thay đổi chưa stage, khôi phục từ index. update-index --skip-worktree đặt cờ trong index local cho file tracked, phục vụ sparse checkout; không phải cơ chế ignore bền vững cho thay đổi local. Bỏ cờ bằng --no-skip-worktree. Không gộp dưới alias “reset file”.
